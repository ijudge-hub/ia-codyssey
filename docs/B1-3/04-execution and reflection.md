## 4. 오류 대응 및 재시도 전략

외부 서비스 연동 자동화는 RSS 응답 오류, Google Sheets 권한 만료, Discord 전송 실패 등의 문제가 발생할 수 있다. 이를 대비해 다음과 같이 운영할 수 있다.

1. **실행 로그 확인**  
   n8n의 Executions 화면에서 실패한 노드와 오류 메시지를 확인한다.

2. **실패 알림 전송**  
   RSS 수집, 시트 기록, Discord 전송 중 오류가 발생하면 관리자용 Discord 채널 또는 이메일로 실패 메시지를 전송한다.

3. **대체 기록 경로**  
   AI 뉴스 시트 기록에 실패하면 별도의 `실패 기록` 시트에 기사 제목과 오류 내용을 남긴다.

4. **재시도 전략**  
   일시적인 네트워크 오류라면 실패한 실행을 재실행한다. 반복적으로 실패하면 API 권한, RSS 주소, 연동 계정 상태를 점검한다.

## 5. 확장 설계

현재 프로젝트 2는 AI 키워드 포함 여부를 기준으로 두 경로로 분기한다. 분기 기준이 늘어날 경우에는 다음과 같이 확장할 수 있다.

- `AI`, `보안`, `반도체`, `모바일` 등 뉴스 카테고리별 분기
- 카테고리별 Google Sheets 탭 및 Discord 채널 연결
- 키워드를 코드에 직접 작성하지 않고 Google Sheets의 설정 표에서 관리
- 생성형 AI를 연결해 기사 제목과 본문을 요약한 뒤 Discord에 전송
- 같은 기사가 반복 저장되지 않도록 링크 또는 GUID 기준 중복 검사 추가

## 6. 노코드 자동화의 한계와 코드 기반 확장

노코드 자동화는 연결과 시각적 분기 구현이 빠르다는 장점이 있지만, 복잡한 데이터 정제·중복 제거·대량 처리에는 한계가 있다.

예를 들어 단순 키워드 분류는 제목에 AI라는 단어가 없어도 AI 관련 기사인 경우를 놓칠 수 있고, 반대로 AI라는 단어만 포함된 비관련 기사를 포함할 수도 있다. 이후에는 Python 또는 JavaScript 기반의 분류 로직과 생성형 AI API를 결합하여 기사 내용까지 분석하는 방식으로 확장할 수 있다.

---

## 7. 회고

이번 과제를 통해 Trigger는 자동화를 시작하는 조건이고, Action은 Trigger 이후 실제 업무를 처리하는 단계라는 점을 확인했다. 또한 조건 분기를 활용하면 동일한 입력도 업무 규칙에 따라 서로 다른 경로로 처리할 수 있었다.

Make는 일반적인 온라인 서비스 연동을 빠르게 구성하기 좋았고, n8n은 데이터 변환, 조건식, 실행 로그 확인 등 복잡한 자동화 흐름을 설계하고 점검하는 데 적합했다. AI 뉴스 자동 수집 프로젝트에서는 이러한 n8n의 장점을 활용해 뉴스 수집, 분류, 기록, 알림을 하나의 자동 실행 흐름으로 구현했다.
