# 02. 자동화 도구 비교 분석

## 1. 비교 대상과 동일 워크플로우

프로젝트 1에서는 **Make**와 **n8n**으로 동일한 고객 문의 자동 분류 워크플로우를 구현했다.

공통 구조는 다음과 같다.

```text
Google Sheets 새 문의 감지
→ 문의 유형 분류
→ 긴급/일반 조건 분기
→ Discord 알림 전송
→ Google Sheets 처리 상태 업데이트
```

두 도구에서 입력 이벤트, 조건 분기 기준, 최종 출력이 동일하도록 설계했다. 따라서 도구의 차이를 기능 자체가 아니라 설정 방식과 운영 관점에서 비교할 수 있었다.

---

## 2. 비교표

| 비교 항목 | Make | n8n | 업무 요구사항 관점 |
|---|---|---|---|
| UI/UX | 원형 모듈과 연결선 중심의 시각적 화면 | 노드와 데이터 흐름 중심의 화면 | 처음 자동화를 구성할 때는 Make가 직관적이며, 데이터 흐름을 자세히 확인할 때는 n8n이 편리했다. |
| 조건 분기 | Router와 Filter를 조합해 분기 | Switch와 If 노드로 분기 | 문의 유형과 긴급도를 나누는 다단계 분기에서는 n8n의 노드 구조가 명확했다. |
| 설정 난이도 | 기본 서비스 연결을 빠르게 시작하기 쉽다 | 노드, 표현식, 데이터 구조 이해가 필요하다 | 단순 업무는 Make가 빠르지만, 규칙이 복잡해지면 n8n이 유리하다. |
| 실행 로그 확인 | 시나리오 실행 기록에서 모듈별 처리 결과 확인 | Executions와 노드별 Input/Output 데이터 확인 | 오류가 발생했을 때 n8n은 어느 단계의 데이터가 문제인지 확인하기 쉽다. |
| 데이터 처리 | 일반적인 SaaS 연동에 적합 | HTTP 요청, XML 변환, 표현식 등 세부 처리 가능 | RSS, XML처럼 형식 변환이 필요한 업무는 n8n이 유연하다. |
| 운영 방식 | 클라우드 기반으로 바로 사용하기 편리 | 로컬 또는 서버 환경에서 운영 가능 | 항상 실행되어야 하는 자동화는 n8n 실행 환경이 유지되어야 한다. |
| 확장성 | 정형화된 반복 업무 자동화에 적합 | API, 표현식, 데이터 변환을 이용한 확장에 유리 | AI API 연동이나 맞춤형 분류 규칙을 추가할 때 n8n이 적합하다. |

---

## 3. Make 분석

### 장점

- 시각적 인터페이스가 직관적이어서 처음 자동화를 구성하기 쉽다.
- Google Sheets, Discord 등 일반적인 협업 도구를 빠르게 연결할 수 있다.
- 단순한 Trigger → Action 구조의 자동화에 적합하다.

### 한계

- Router와 Filter가 많아지면 시나리오 화면이 복잡해질 수 있다.
- 세부 데이터 변환이나 복잡한 조건식은 추가적인 설정이 필요하다.

### 적합한 상황

Google Sheets에 새 데이터가 들어오면 Discord에 알림을 보내는 것처럼, 비교적 단순하고 정형화된 업무 자동화에 적합하다.

---

## 4. n8n 분석

### 장점

- 노드별 입력값과 출력값을 확인할 수 있어 디버깅이 편리하다.
- Switch, If, HTTP Request, XML 등 다양한 노드로 복잡한 흐름을 설계할 수 있다.
- 표현식을 활용해 업무 규칙을 세밀하게 구현할 수 있다.

### 한계

- 처음에는 노드 구조와 데이터 형식을 이해하는 시간이 필요하다.
- 로컬 환경으로 운영할 경우 자동 실행을 위해 n8n이 실행 중이어야 한다.

### 적합한 상황

조건 분기가 많거나, RSS·XML·API처럼 데이터를 가공해야 하는 업무에 적합하다. 향후 AI 분류, 자동 요약, 외부 API 연동으로 확장할 때도 활용하기 좋다.

---

## 5. 프로젝트 2에서 n8n을 선택한 이유

프로젝트 2는 Google News RSS를 수집하고 XML을 JSON으로 변환한 뒤, 기사 제목의 키워드를 기준으로 AI 뉴스와 일반 뉴스로 분기해야 했다.

따라서 다음 비교 항목을 근거로 n8n을 선택했다.

1. **조건 분기 구조**  
   If 노드에서 기사 제목에 `OpenAI`, `ChatGPT`, `생성형 AI` 등의 키워드가 포함되었는지 직접 판별할 수 있었다.

2. **데이터 처리와 확장성**  
   HTTP Request와 XML 노드를 사용해 RSS 데이터를 처리할 수 있었다. 향후 생성형 AI API를 연결해 키워드 기반 분류를 문맥 기반 분류로 발전시키기도 쉽다.

3. **실행 로그 확인 방식**  
   각 노드의 입력과 출력 데이터를 확인할 수 있어, 어떤 기사가 AI 뉴스 또는 일반 뉴스로 분류되었는지 검증할 수 있었다.

결론적으로 Make는 빠른 시작과 단순한 서비스 연결에 강점이 있고, n8n은 복잡한 데이터 처리와 조건 분기, 확장성 측면에서 강점이 있다.
